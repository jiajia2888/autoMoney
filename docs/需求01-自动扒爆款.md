# 需求 01：自动扒爆款

日期：2026-11-08。用户原始目标：输入一个抖音对标账号，自动整理出点赞过万的爆款视频。

## 可行性结论

从现有源码看可以实现：已有按账号获取作品、作品详情及点赞数量的代码，需增加产品任务、过滤与展示。当前仅完成静态源码核对，没有实际账号输入，也没有联网抓取验证，不能据此承诺接口当前一定可用。

## 首版需求口径

以下是建议默认值，非用户已确认的额外要求：

- 输入：先支持抖音完整主页链接；底层可接 sec_user_id。昵称、公开抖音号和分享短文案的识别后续补充，不将其误当 sec_user_id。
- 规则：“过万”暂按原始整数点赞数 > 10000，10000 不入选，10001 入选。不要用界面四舍五入的“1.0万”判断。
- 范围：先取公开可访问作品，过滤图文作品，仅整理视频；采集数量/时间范围应在任务启动前明确。
- 输出：封面、标题/描述、发布时间、点赞数、评论数、收藏数、分享数、抖音原链接，按点赞数降序。
- 显示本次扫描数量、符合数量、扫描范围及停止原因。达到上限时标记部分扫描，不能称已取到账号全部爆款。
- 首版“扒”指整理视频清单与原链接；批量下载、转写与 AI 内容分析不是本次已经要求或完成的能力。
- 点赞过万属于确定性筛选，无需大模型参与判断；后续可在选中视频之上增加 AI 选题归纳等分析。

## 推荐接入链路

前端提交主页与扫描范围 → Go 创建任务 → Python 适配层复用 DouYinClient 分页 → 提取并验证原始点赞整数 → 过滤视频与 >10000 → 去重保存 → 前端展示结果。

Go 通过 service/benchmark/Crawler 边界对接，任务支持查询状态和取消，避免在一次 HTTP 请求里等待全部作品抓完。
第一步无需逐条采集评论或下载所有视频；优先复用分页客户端，验证列表字段是否足够，只在字段缺失时补作品详情。
不直接照搬现有完整 creator 流程，避免多抓评论和无关媒体。

## 接入需要补的部分

1. 校验账号输入与短链接解析边界；账号与作品保留稳定关联。
2. 分页加入数量上限、时间范围、限速、重复游标检测、作品 ID 去重、超时与取消；不能因为某一条点赞低就提前停止。
3. 检查 HTTP 和平台业务错误，缺失/无效点赞字段不能伪装成 0；区分未登录、验证、访问受限、正常无匹配。
4. 增加任务与结果表、显式迁移、任务 API 和列表页面。
5. 验证真实登录态与一条账号的抓取结果；与页面可见数据抽样核对，记录抓取时间。
6. 原专家包装脚本与当前后端版本不同；归档相关脚本不可直接认定兼容。

## 验收条件

- 对合法主页输入，能启动任务并看到进度，结束后只展示符合条件的视频。
- 9999、10000、10001 的阈值边界符合 >10000；图文即使过万也不混入视频清单。
- 同一作品重复出现在分页结果中只保留一条。
- 登录失效、接口异常与任务取消有真实状态，不返回“0 条爆款、成功”掩盖异常。
- 数量/时间上限触发时，结果标记扫描不完整并说明停止原因。
- 原链接可打开，数据标明抓取时间；无法访问的私密/删除内容不承诺覆盖。
