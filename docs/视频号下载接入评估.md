# 视频号下载接入评估

2026-11-10；配套项目比较和固定版本来源见 [GitHub调研](GitHub视频号下载方案调研.md)。本文记录此前公开源码研究与接口探测；当时没有接通下载或变更应用。后续元宝登录和单条下载代码已接入，最新真实验证状态见[交接文档](handoff.md)。

## 结论

可以与现有系统组合，优先验证“投手接口筛作品 → 官方分享链接 → 元宝解析 → 带token的微信预览接口 → 媒体下载”。它补的是媒体来源，不替换已成功的作者监控和过万筛选。Mac可用且无需为此先安装微信抓包证书。

候选来源是 QinGeneral/wx-downloader 的 client.py 与 ltaoo/wx_channels_download 的 yuanbao.go；仅研究协议，未复制其代码进产品。两个仓库均有许可证附加限制，后续如复用源码须按各仓库完整LICENSE处理。

“源码支持这条路”与“本机已经下载成功”分开：本轮匿名调用元宝接口实际HTTP401，未取得播放地址，视频文件仍为0。下一次真实验证需要用户在元宝官网完成独立登录。现有视频号投手Cookie不能视为元宝Cookie，不读取其他项目或普通浏览器配置作为替代。

## 已核对的链路差异

| 阶段 | 当前系统 | 拟验证的补充 |
| --- | --- | --- |
| 筛选 | 投手getFinderObject，作者2、徐晶说、大拇指>=100000共35条 | 沿用原筛选，100002继续按10万+展示 |
| 分享 | getObjectShortLink取得weixin.qq.com/sph链接 | 沿用现有接口 |
| 播放凭证 | 曾直接用shortUri、空generalToken请求预览，35条均业务不可播放 | 先由元宝解析同一分享链接取得playable_url中的token/eid |
| 预览 | finder-preview/api/feed/get_feed_info | 请求baseReq.generalToken=token、exportId=eid |
| 媒体 | 当前未取得 | 源码从feedInfo.h264VideoInfo.videoUrl、videoUrl或h265VideoInfo.videoUrl取候选 |
| 下载 | 仅抖音已交付 | 视频号必须另验媒体格式、完整性与身份后再接网页 |

元宝请求契约（来自上述项目源码，非腾讯承诺稳定的开放API）：

```text
POST https://yuanbao.tencent.com/api/weixin/get_parse_result
Content-Type: application/json
{"type":"video_channel_url","url":"<官方分享链接>","scene":1}

需要实测的成功字段：code=0、data.playable_url
playable_url必须为https://channels.weixin.qq.com/finder-preview/...并带token、eid。
```

预览接口即之前使用的微信接口，但请求凭证来源不同。不能把两种请求条件混为一次失败，也不能据此保证元宝登录后全部成功。媒体是否还需解密以实际文件为准；这条源码路径本身没有decodeKey或解密步骤，抓包方案的ISAAC64算法不能直接代替缺失的播放地址。

ltaoo的“无元宝Cookie”说明也不能解释为匿名元宝API：本次固定版本client.go在无Cookie时退回已连接微信页面的WebSocket请求，仍需另一种运行条件。

## 本机验证与准备

- 公开GitHub搜索及项目源码读取成功，版本、许可证和来源由配套调研文档记录。
- 使用现有35条清单中的1条真实官方分享链接，以type=video_channel_url、scene=1向元宝POST，不发Cookie，也不照抄源码内固定的用户/设备标识；实际HTTP401 Unauthorized。没有取得playable_url或媒体。
- 未运行下载器安装程序或第三方源码，未安装证书、修改系统代理、访问普通浏览器登录态、购买第三方API或迁移数据库。
- 对照当前本地数据库重新核对35个目标，全部有此前取得的官方分享链接。已准备以下输入，未执行批量下载：
  - `.local/downloads/wechat/徐晶说-大拇指10万以上/元宝下载输入.json`：`{"links":[{"url":...,"title":...}]}`，符合QinGeneral CLI输入契约。
  - 同目录`元宝下载关联清单.json`：保留本地video_id、原始export_id、分享URL、标题、大拇指数与日期，便于逐条回填。
  - 同目录`元宝匿名接口核验.json`：HTTP401与0文件的脱敏记录，不含任何凭据或token。

## 验证成功后怎样接现有项目

1. **独立的元宝会话。** 登录入口与视频号投手身份分开；只向元宝官网发送本次元宝凭据。用项目独立profile/受限凭据文件，默认不自动弹出登录、不扫描其他工具配置。会话存在不能直接显示“视频可下载”，须有本次接口结果。
2. **新增媒体解析适配器。** service层接收已收录的视频ID，查作者平台、原始exportId和nonce，再取得分享URL；不开放任意URL代理。POST元宝后只接受指定官方HTTPS预览地址，取出token/eid。token只在内存使用，接口/日志不回显，不持久保存签名媒体URL。上游身份和原始ID若能核对则必须核对，保留source_url映射，不能按同名标题自动关联。
3. **下载能力共用，媒体来源分平台。** 目前service/download只允许抖音固定URL，不能直接移除校验让视频号走抖音脚本。抽出Resolve与受限文件下载边界；dy继续现有脚本，wx使用新解析器。原始视频号exportId是含分隔符的不透明字符串，不直接拼文件路径；采用数据库video_id或摘要命名，并用元数据保存原ID。
4. **保留既有下载约束。** 官方媒体域名与每跳重定向校验、TLS验证、CDN不发登录Cookie、超时/取消/数量与文件大小限制、临时文件原子发布、ffprobe视频流及完整解码验证。源码中的任意媒体URL、自动跨域重定向或只检查文件头不直接照搬到后端。
5. **先单条，再35条。** 先用已知作品核对画面、作者、日期、时长和完整MP4，随后页面开放“下载视频/保存MP4”及受限Range读取。批量按现有35条固定快照串行运行，去重，凭证过期只重新解析，429退避，分别报告成功/跳过/失败；不将同一分享URL返回的错误页存为MP4。
6. **明确实际状态。** 区分需要元宝登录、预览不可播放、未返回媒体、格式/解密异常、文件成功；网页失败提示不能让用户反复更新抖音Cookie。批量结果回填下载任务，不改点赞门槛或首次过万日期。

下一步是在用户方便时完成一次元宝官网登录，用同一条分享链接先做真实验证。本轮已把查询、源码比较、失败条件与35条输入准备好，不需要现在唤醒用户扫码。若元宝路线失败，再评估独立运行的Mac捕获工具导出媒体描述/文件接入；这类工具的证书和代理要求属于另一个实施决策。
