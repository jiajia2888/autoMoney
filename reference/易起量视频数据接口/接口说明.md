# 易起量方案：视频号作品数据接口交付说明

版本：1.0.0｜核对日期：2026-11-09（Asia/Shanghai）

范围：易起量加热平台投手号的网页扫码、Cookie 会话、外部作者查询、作品元数据及分享链接。本文只描述易起量方案，不包含其他接入方式。

## 1. 可以交付哪些能力

| 能力 | 结论 | 验证情况 |
| --- | --- | --- |
| 网页扫码登录投手号、读取身份 | 支持 | 用户手机扫码后真实通过 |
| 按昵称/关键词查询作者 | 支持 | 真实返回非空作者列表 |
| 查询指定外部作者的作品 | 支持 | 真实返回 5 条作品；另验证两页各 1 条 |
| 视频文案、封面、发布时间、作者 | 支持 | 真实返回对应字段 |
| 爱心点赞、拇指点赞、转发、评论数量 | 支持 | 真实返回 4 项整数计数 |
| 获取视频号分享链接 | 支持 | 真实取得 `https://weixin.qq.com/sph/...` |
| 全站关键词搜索视频 | 尚未验证通过 | 不指定作者的搜索返回空 `feedInfos` |
| 外部视频的评论正文和回复 | 尚未验证通过 | 投手 Cookie 调用助手接口返回 `300330`；助手会话补测外部评论返回 `300800` |
| 播放量、完播率、观看时长、观众画像 | 未验证可通过本作品接口获取 | 不在此次外部作品实测响应中 |
| 收藏数 | 未确认 | 不能将 `favCount` 解释为收藏数 |
| MP4 下载直链、视频文件下载 | 尚未验证通过 | 已取得分享链接，但未从分享页取得可用媒体地址 |

这里的“支持”是本次样本和接口路径实测成立，未承诺覆盖全部作者、全部作品或无限历史数据。计数反映查询时返回的值，没有独立核验平台的更新时间和统计口径。

## 2. 包内文件与接入选择

- `微信上游.openapi.json`：微信官网请求契约，适合开发独立服务端适配器。
- `易起量业务.openapi.json`：本机易起量项目已有业务路由，适合接入现有易起量部署。
- `wechat_promote_client.py`：独立 Python 示例，使用自有投手 Cookie 请求作者、作品和分享链接。
- `作品响应样例.json`：结构来自实测；计数保留一条样本，身份、文案、URL、ID 和分页游标均替换为示意值。
- `验证记录.md`：源码依据、实测范围及未通过项。
- `requirements.txt`：示例所需依赖。

两份 OpenAPI 均可导入支持 OpenAPI 3.0 的 Apifox、Postman、Swagger Editor 等工具。导入仅建立接口定义，不代表目标服务已经部署或全部接口已经线上验收。

**选择其中一种接入方式：**

1. 已有易起量部署：调用其业务 API，业务系统持有易起量的 `JWT`；易起量后台管理微信 Cookie。
2. 自建采集服务：调用微信上游 API，自建扫码会话管理和加密 Cookie 存储。

当前项目新增的是验证工具，尚未发布一套新的、供业务系统调用的投手 Cookie 采集服务。不要把文档中的微信域名、易起量域名和任意本地服务地址互换。

本文依据本机源码与实际官网请求编写。这里的官网页面内部接口不等同于微信对第三方公开承诺的开放平台 API。

## 3. 视频字段字典

外部作品上游路径：`data.objects[]`。

| 字段 | 实测类型 | 业务含义与处理方式 |
| --- | --- | --- |
| `exportId` | string | 网页作品标识；原样保存，供分享链接等接口使用 |
| `globalExportId` | string | 平台返回的另一作品标识；原样保留，不推断跨账号稳定性 |
| `nonce` | string | 作品附加标识；取分享链接时映射到请求 `nonceId` |
| `description` | string | 视频文案/描述；不是语音转写或字幕 |
| `coverUrl` | string | 封面图片 URL；不是视频文件地址 |
| `createTime` | integer | Unix 秒时间戳；前端 `new Date(createTime * 1000)` |
| `likeCount` | integer | **爱心点赞数**，按易起量现有“爱心”映射；不将其与拇指数合并 |
| `favCount` | integer | **拇指点赞数**，按易起量现有“拇指”映射；不要标为收藏数 |
| `forwardCount` | integer | 转发/分享数量；不同分享渠道的细分口径未核验 |
| `commentCount` | integer | 评论数量；不代表已经取得评论正文，也不保证等于可分页取回的条数 |
| `accountInfo` | object | 作者信息，见下表 |
| `flag` | object | 平台状态/能力标记；不是整数枚举，按对象保留 |
| `deleteTime` | integer | 删除时间相关字段；样本为 0，语义和所有状态未逐项核验 |
| `shoppingcartJumpinfo` | object | 商品跳转扩展信息；允许空对象，不承诺商品详情完整 |
| `finderComponent` | object | 组件扩展信息；保留原始结构，未做业务枚举核验 |
| `profitableType` | integer | 平台扩展枚举，未核验具体取值含义 |
| `inquireInfo` | object | 平台扩展信息，未核验完整结构 |

作者字段位于作品的 `accountInfo`，或作者搜索的 `data.list[]`：

| 字段 | 含义 |
| --- | --- |
| `username` | 作者 `finder_id`，可用作作品查询的 `encryptedUsername`；不要与执行请求的投手账号混淆 |
| `nickName` | 作者昵称，注意大小写，不是 `nickname` |
| `headImgUrl` | 作者头像 |
| `signature` | 作者简介 |
| `authImgUrl`、`authProfession` | 认证相关展示字段；允许空值 |
| `exportUsername` | 部分作者信息中出现的另一身份字段，按原样保留；不是本次作品查询采用的参数 |
| `gender`、`liveStatus`、`permission`、`roi2PromoteFlag`、`isPrivate` | 源响应中的状态字段，不为未经核验的枚举编造显示文案 |

示例计数（2026-11-09 补测）：`likeCount=899`、`favCount=826`、`forwardCount=218`、`commentCount=15`。这是某条公开作品的返回样本，不是固定值。

**此前把 `favCount` 称为“收藏”不准确，本交付以“拇指点赞”更正。** 此口径依据易起量后端注释和前端指标标签；如需精确对外定义，应再与官网展示逐项对照。

未返回的计数应存 `null` 或标记未知，不能补成 0。不要将投放报表的 `exposureCount` 作为任意外部作品的自然播放量，也不要把某个投放计划的增量指标当作作品全部累计指标。

## 4. 上游公共约定

基础地址：`https://channels.weixin.qq.com`。全部接口均为 `POST`。

| 事项 | 规则 |
| --- | --- |
| 投手登录凭据 | 请求 Cookie：`promotewebsessionid=<自行扫码取得的值>` |
| 获取 token / 查询扫码状态 | 不要求已有投手 Cookie；确认登录的响应通过 `Set-Cookie` 下发会话 |
| 身份/登录类请求体 | JSON，`Content-Type: application/json` |
| 搜索/作品/分享请求体 | 表单，`application/x-www-form-urlencoded`，不是 multipart |
| `_pageUrl` | URL 查询参数；值由 HTTP 客户端编码一次，见各接口 |
| 成功判断 | 同时检查 HTTP、顶层 `error`、`errCode`、`data.baseResp.errcode/errCode` 和所需业务字段 |
| HTTP 201 | 此类接口常用成功状态；不能只接受 200 |
| 会话有效期 | 未验证固定时长；以身份接口和业务错误为准，过期重新扫码 |
| 访问位置 | 由自己的后端访问；不建议把 Cookie 交给业务前端浏览器直接跨域调用 |

易起量源码还构造 `_aid`、`_rid`、`_biz_uin` 等查询参数；本次最小请求只携带 `_pageUrl` 即已通过上述只读接口。不能据此承诺这些参数永远可省略。

原源码在部分表单中构造 `baseReq={featureFlag:26}`。本次补测已验证：作者搜索、作者作品两接口可以省略 `baseReq`。本交付的最小表单不包含该嵌套对象，避免不同 HTTP 库的字典编码差异。

## 5. 微信上游接口

### U1. 取得投手扫码 token

`POST /promote/api/web/auth/auth_login_token`

查询参数：`_pageUrl=https://channels.weixin.qq.com/promote/pages/platform/login-iframe`。

JSON 请求体：`{}`。响应示意：

```json
{"data":{"token":"EXAMPLE_QR_TOKEN"}}
```

本次 `data` 中只观察到 `token`。应保留整个 `data`，供下一步原样传回，不要丢弃未来增加的字段。

二维码内容是以下 URL 文本，需自行生成二维码图片：

```text
https://channels.weixin.qq.com/promote/pages/mobile_login?token=<data.token>
```

### U2. 查询扫码状态

`POST /promote/api/web/auth/auth_login_status`

查询参数同 U1。JSON 请求体为 U1 返回的整个 `data`，例如 `{"token":"EXAMPLE_QR_TOKEN"}`。

| `data.status` | `data.acctStatus` | 易起量处理 |
| --- | --- | --- |
| 0 | 不限定 | 等待扫码 |
| 5 | 1 | 已扫码，等待手机确认 |
| 1 | 1 | 已确认，读取响应 `Set-Cookie`，然后用 U3 核验身份 |
| 4 | 不限定 | 二维码过期，重新生成 |
| 其他组合 | 任意 | 未确认的状态，不当作成功 |

上述状态来自易起量状态机；本次观察到等待、已扫码、已确认。建议每 2 秒轮询并设置本地超时，该间隔是实现建议，不是已测得的平台配额。

### U3. 核验投手身份

`POST /promote/api/web/transfer/MMFinderPromotionLiveDspApiSvr/getLivePromotionUserProfile`

查询参数：`_pageUrl=https://channels.weixin.qq.com/promote/pages/platform/home`。

JSON 请求体 `{}`，携带投手 Cookie。读取 `data.selfAccountInfo.username` 作为执行账号身份；昵称字段是 `nickName`。仅在身份有效后将会话加入账号池。

### U4. 搜索作者

`POST /promote/api/web/transfer/MmFinderPromotionApiSvr/searchAccount`

查询参数：`_pageUrl=https://channels.weixin.qq.com/promote/pages/platform/create-order`。

表单字段：

| 字段 | 是否需要 | 说明 |
| --- | --- | --- |
| `query` | 是 | 作者搜索关键词/昵称 |
| `flag` | 是 | 本次验证值 1，对应易起量选择加热视频的作者搜索；其他值未在本交付验证 |
| `currentPage` | 是 | 从 1 开始 |
| `pageSize` | 是 | 本次验证 1、5；上限未核验 |

响应：`{"data":{"list":[作者对象],"totalCount":整数}}`。作者搜索返回的 `username` 用于 U5；搜索可能存在重名，应按身份选择，不能只按昵称绑定。

### U5. 取得作者作品与互动计数

`POST /promote/api/web/transfer/MmFinderPromotionApiSvr/getFinderObject`

查询参数同 U4。表单字段：

| 字段 | 是否需要 | 说明 |
| --- | --- | --- |
| `encryptedUsername` | 是 | 目标作者的 `username`，不是执行请求的投手 `finder_id` |
| `startTs` | 是 | 时间范围开始，Unix 秒，示例按字符串发送 |
| `endTs` | 是 | 时间范围结束，Unix 秒，不能传毫秒 |
| `limit` | 是 | 每页条数，本次验证 1、5；易起量前端常用 15，上限未核验 |
| `lastBuf` | 后续页需要 | 首次不传；下一页原样传上次 `data.lastBuf` |

响应：

```json
{"data":{"objects":[],"continueFlag":false,"lastBuf":""}}
```

非空样例见 `作品响应样例.json`。`continueFlag=true` 时，使用返回的游标查询下一页；更换账号、作者或时间范围必须从第一页重新开始。游标视为不透明字符串，不解析、不自行编码或生成。若游标重复、缺失或返回空页，应终止本轮并记录原因，不能无限循环或宣称已取得全部作品。

本次补测在同一会话、作者、时间范围下，用真实游标连续取得两页各 1 条，作品不同。尚未测试跨会话复用游标，也未验证翻到历史末页。

### U6. 取得视频号分享链接

`POST /promote/api/web/transfer/MmFinderAssistantBroker/getObjectShortLink`

查询参数：`_pageUrl=https://channels.weixin.qq.com/promote/pages/platform/short-video/detail`。

表单字段：`exportId=作品.exportId`、`nonceId=作品.nonce`。

响应示意：

```json
{"data":{"shortUrl":"https://weixin.qq.com/sph/EXAMPLE"}}
```

本次已真实取到 `shortUrl`。**它是分享页入口，不是 MP4 文件直链。**

### U7. 作品筛选接口（未验证有效数据）

`POST /promote/api/web/transfer/MMFinderPromotionLiveDspApiSvr/searchFinderObject`

查询参数同 U4。表单参数：`query`、`targetUsername`、`limit`、`offset`。

源码将其用于作品查询。本次 `targetUsername=""`、`query="风景"` 时，得到 `data.feedInfos=[]`；不能据此当作已实现全站关键词视频搜索，也不将其列为首版业务依赖。OpenAPI 将其标记为未验证能力。

## 6. 易起量已有业务接口

基础地址替换为实际易起量部署地址；OpenAPI 中的 `https://yiqiliang.example.com` 只是占位符。

鉴权：`Authorization: JWT <易起量业务登录token>`，不是 `Bearer`，也不是微信 Cookie。POST 使用 JSON。后台会根据执行账号 `finder_id` 读取自己的 Cookie 缓存。

以下路由已从本机后端和前端对应源码交叉核对，**本次没有调用易起量生产环境验收这些路由**。已验证的是它们背后的相关微信上游请求。

| 编号 | 方法与路径 | 入参及说明 |
| --- | --- | --- |
| B1 | `GET /api/wx/wx_user/login_qrcode/` | 返回 `data.qrcode`、`data.tid`；`qrcode` 是二维码内容 URL 文本，不是图片二进制 |
| B2 | `GET /api/wx/wx_user/get_qrcode_status/?tid=...` | 完成时 `data.status=SUCCESS`，读取 `data.finder_id`；同时检查外层 `code` |
| B3 | `GET /api/wx/wx_user/get_bind_wx_user_list/` | 可传 `online=1&status=1`；普通账号按其权限过滤，管理账号可能需要 `user_id` 等上下文 |
| B4 | `POST /api/wx/wx_search_account/` | `finder_id`（执行投手）、`query`、`flag=1`、`currentPage`、`pageSize` |
| B5 | `POST /api/wx/wx_video_plan_detail/show_video_list/` | `finder_id`（执行投手）、`username`（目标作者）、`limit`、`lastBuf`，以及时间条件 |
| B6 | `POST /api/wx/wx_video_plan_detail/get_video_short_link/` | `export_id`、`nonce_id`；后端自动选择当前用户可用投手，未显式按请求 `finder_id` 选择 |

B5 时间条件二选一：

- 近 N 天：`days` 传正整数，如 90。
- 自定义范围：不传 `days`，传数值类型 `start_time`、`end_time`，单位为 **Unix 毫秒**。该业务路由会除以 1000 后转给 U5。

这是易起量业务接口与微信上游接口之间最易混淆的差别：**B5 自定义时间用毫秒，U5 用秒**。

B4 请求示例：

```json
{"finder_id":"v_executor@finder","query":"作者昵称","flag":1,"currentPage":1,"pageSize":5}
```

B5 请求示例：

```json
{"finder_id":"v_executor@finder","username":"v_target@finder","days":90,"limit":5}
```

### 响应嵌套与特殊情况

易起量 `DetailResponse`：`{"code":2000,"data":接口结果,"msg":"获取成功"}`。错误通常是 `{"code":400,"data":null,"msg":"..."}`，HTTP 状态仍可能是 200。

B4/B5 把上游完整响应放进 `data`，因此：

- 原始 HTTP JSON 的作者数组是 `body.data.data.list`。
- 原始 HTTP JSON 的作品数组是 `body.data.data.objects`。
- 前端封装 `request.js` 已返回外层 `body.data`，在其 `.then(res)` 中才读取 `res.data.objects`。

B6 返回：

```json
{"code":2000,"data":{"video_url":"https://weixin.qq.com/sph/EXAMPLE"},"msg":"获取成功"}
```

**虽然字段名为 `video_url`，实际来源是微信的 `shortUrl`，仍然是分享链接。不要以这个字段名判断它可作为视频文件下载地址。**

B1/B2 依赖易起量已配置的 Redis/Celery；缺少任务队列、投手绑定额度不足、账号归属不符或登录失败时会报错。不要仅凭任务后台状态 `SUCCESS` 忽略外层业务 `code` 和身份结果。

B3 的序列化器支持动态字段 `feed_cookie`，可能暴露原始登录凭据。第三方业务通常只需要 `finder_id`、`finder_name`、`online`、`status`；交付网关应按这些字段返回，避免向业务前端透传完整账号原始响应。包内没有包含任何真实 Cookie 或 JWT。

## 7. 下载能力说明

本方案已验证的链路：`投手扫码 → Cookie → 查询作品 → exportId+nonce → 分享链接`。

尚未验证通过的链路：`分享链接 → 可用媒体地址 → 保存可播放的视频文件`。

本次调用分享页的 `get_feed_info`：直接请求曾返回 HTTP 401；先访问公开分享页再请求后，出现 HTTP 201、`errCode=0`，但 `data` 仅含 `errMsg`，没有视频对象或媒体地址。这说明必须验证业务数据，不能将 HTTP 成功、`errCode=0` 或返回了 URL 当作下载实现成功。

`coverUrl`、`shortUrl` 和易起量 `video_url` 都不能当作已确认的 MP4 直链。后续如取得媒体地址，还需验证地址有效期、必要请求头、媒体格式、是否加密及文件完整性。本交付不提供未验证的“视频文件下载 API”，也不写入一个并不存在的下载接口。

## 8. 业务开发建议与验收清单

建议上层业务保留原字段，并增加 `executor_finder_id`、`target_finder_id`、`collected_at`（Unix 秒或明确时区时间）以及 `source="wechat_promote_web"`。

- 将身份、游标、`exportId`、`globalExportId`、`nonce` 全部按字符串保存。
- `likeCount` 与 `favCount` 分列展示，不默认相加，不宣称其中一个是收藏数。
- 未知字段为空；无法获取的播放量和下载地址留空，不伪造 0 或用封面替代。
- 同一作者的分页保持账号和时间范围不变；游标原样传递，按作品 ID 去重。
- 日增量需要自建历史快照相减；单次接口返回没有增长趋势或历史时序。
- 接口异常分为网络失败、业务失败、登录失效、空结果和格式变化；未知错误不直接归为登录失效。
- 上游投手常见失效码 `-330/-333/-334`、`data.baseResp` 中部分失效码来自源码处理逻辑，实际应记录脱敏错误并重新核验身份。`300330` 和 `300800` 属于前述助手接口补测，不能不分接口通用解释。
- 平台配额和规模吞吐未验证；示例串行、限页执行，不是生产调度器。

首版可验收：扫码后身份正确；作者检索非空；指定外部作者作品有文案及 4 类计数；相同条件能翻两页且无重复；取得分享链接；会话失效能提示重新扫码；日志及交付产物不包含凭据。

## 9. 示例运行

```powershell
python -m pip install -r requirements.txt
# 在你自己的安全运行环境中设置 PROMOTE_WEB_SESSION_ID；不要提交或转发真实值。
python wechat_promote_client.py --keyword "作者昵称"
python wechat_promote_client.py --author "v_target@finder" --days 90 --pages 2 --limit 5
python wechat_promote_client.py --author "v_target@finder" --pages 1 --share
```

示例读取环境变量 `PROMOTE_WEB_SESSION_ID`，其值为 Cookie 的值部分，不含 `promotewebsessionid=`。`--share` 只为本轮第一条作品取得分享链接；不会把分享页 HTML 保存成 MP4。

示例类中另提供 `login_challenge()`、`poll_login()`、`profile()`，便于接入自己的二维码页面。示例 CLI 不会替业务系统实现完整扫码 UI、长期会话管理、多账号调度或文件下载。
